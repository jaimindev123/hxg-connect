How it works

Every HXG Connect workspace has a private address for each platform it connects. A platform sends a lead to that address, and within a second or two the lead is in the CRM: checked for duplicates and assigned to a salesperson by the workspace's rules.

https://yourworkspace.hxgconnect.com/api/webhooks/in/{platform}/{your-key}

You get the addresses in HXG Connect under Settings > Integrations > Websites, marketplaces and other platforms. Save the integration once, pick a platform, and copy its address. The same screen has a Send test button and a log of recent deliveries.

There is no field mapping to do. Platforms disagree about names (phone, Mobile No., your-tel, SENDER_MOBILE), so we read whatever arrives and work out which value is the name, the mobile number, the email and the message.

One rule: a lead needs a mobile number. An enquiry with only an email address is not added; it waits under "Couldn't be added" on the setup screen. Make the phone field required on your forms.

Send your first lead

Copy the address for Any other platform and run this from any terminal:

curl -X POST "https://yourworkspace.hxgconnect.com/api/webhooks/in/custom/YOUR-KEY" \
  -H "Content-Type: application/json" \
  -d '{"name":"Asha Verma","phone":"9820012345","email":"asha@example.com","message":"Interested in a 2BHK"}'

You get back:

{"status":"success","message":"Lead added"}

Open Leads in HXG Connect and Asha is there.

Fields we read

Send JSON (application/json), a normal form post (application/x-www-form-urlencoded) or multipart/form-data. Nesting is fine: we look inside objects, and inside lists of {"label": …, "value": …} pairs.

Anything else at the top level of what you send (up to 18 short values) is kept on the lead as extra details. Passwords, tokens, captcha answers and consent tick-boxes are dropped.

Lead source. The source is the platform in the address: wordpress, shopify, indiamart and so on. On the custom address you choose it by adding ?source=property_expo_2026.

Replies

StatusBodyMeaning
200{"status":"success","message":"Lead added"}A new lead was created and assigned.
200{"status":"success","message":"Existing lead updated"}That mobile number is already a lead. The new enquiry was added to its timeline.
200{"status":"success","message":"Already received"}Same reference as an earlier delivery. Nothing was added twice.
200{"status":"held","message":"Received, but not added: …"}Only on platforms that switch a webhook off after errors (Shopify, IndiaMART, Typeform and similar). The entry waits for a person to look at it.
422{"status":"failed","message":"No mobile number found…"}The lead couldn't be read. Fix the payload and send again. Used on WordPress, automation tools and custom.
401{"status":"failed","message":"Signature check failed"}Shopify or Typeform secret doesn't match the one saved in HXG Connect.
404{"status":"failed","message":"Unknown address"}Wrong platform name or key. Copy the address again.
429More than 240 leads in a minute on one address. Wait and retry.

Opening an address in a browser (a plain GET) answers {"status":"ready"}, which is a quick way to check you copied it correctly.

Duplicates and retries

  • One buyer, one lead. Leads are matched on mobile number within a workspace. The same buyer coming from your website on Monday and IndiaMART on Thursday stays one lead with two entries on the timeline.
  • Retries are safe. If your system sends a reference (see the table above) and repeats a delivery, we answer "Already received". Without a reference, a repeat is still caught by the mobile number and shows as a second enquiry on the same lead.
  • If we don't answer within your timeout, or answer 5xx, retry with the same reference. A sensible schedule is 1 minute, 5 minutes, 30 minutes, then hourly for a day.
  • Assignment. New leads are assigned by the workspace's rules (source, location, budget, property type, round-robin). You can't choose the salesperson from outside.

Security

  • The address is the credential. The key in it is long and random. Anyone holding the address can add leads to that workspace and nothing else: it can't read, change or delete anything. Don't put it in public page source; for browser forms use the website key instead.
  • HTTPS only in production.
  • Signed deliveries. For Shopify and Typeform, save the platform's signing secret in HXG Connect and unsigned posts to that address are refused.
  • If an address leaks, press Disconnect on the integration and set it up again. Every address gets a new key and the old ones stop working at once.
  • What we keep. The delivery log shows the lead's name and the last four digits of the number. The full payload is stored only when a lead couldn't be added, so someone can enter it by hand.

WordPress plugin

One plugin covers the common form builders, with no per-form setup: Contact Form 7, WPForms, Elementor Pro, Gravity Forms, Ninja Forms, Fluent Forms, Formidable Forms, and optionally WooCommerce orders.

  1. In HXG Connect, choose WordPress on the connector screen and press Download the WordPress plugin.
  2. In WordPress: Plugins > Add New > Upload Plugin, choose the zip, activate.
  3. Open Settings > HXG Connect Leads, paste your WordPress address, save.
  4. Press Send test lead. The page lists which form plugins it found and shows the result of each send.

Your forms keep working as before: emails still go out and entries are still saved in WordPress. The plugin sends the enquiry before the email step, so a broken mail setup on the site doesn't cost you leads.

Elementor Pro without the plugin. In the form widget, add Actions After Submit > Webhook and paste the same address. Both the simple and "Advanced data" formats are read.

Developers can add or change what is sent with the hxg_connect_leads_payload filter:

add_filter( 'hxg_connect_leads_payload', function ( $payload, $plugin ) {
    $payload['project'] = 'Sunrise Heights';   // tag every lead from this site
    return $payload;                            // return false to skip a submission
}, 10, 2 );

Shopify

  1. Shopify admin: Settings > Notifications > Webhooks > Create webhook.
  2. Event Customer creation, format JSON, URL = your Shopify address. Save.
  3. Add a second webhook for Order creation if buyers should become leads too. The lead is the customer; the order number, total and items go on the timeline.
  4. Copy the signing secret Shopify shows below the webhook list into Shopify webhook signing secret in HXG Connect.

We verify Shopify's X-Shopify-Hmac-Sha256 header against that secret and use X-Shopify-Webhook-Id to ignore retries. Shopify removes a webhook after repeated failures, so this address always answers 200; customers without a phone number show up under "Couldn't be added".

Shopify's theme contact form sends an email and creates nothing we can listen to. To capture those, use the website snippet on the contact page, or a form app that creates a customer.

Wix

  1. Dashboard > Automations > new automation.
  2. Trigger: Wix Forms: form submitted. Action: Send via webhook.
  3. Target URL = your Wix address. Keep "All keys and values". Activate.

Webflow

  1. Site settings > Apps & integrations > Webhooks.
  2. Add a webhook with trigger type Form submission and your Webflow address.
  3. Publish and submit the form once.

Any HTML form website key

For a hand-built site, use a website key instead of a connector address. A website key is safe to place in page source: it can only create leads, and you can revoke it. Create one in HXG Connect under Settings > Lead capture > Website forms, which also gives you a ready-made snippet.

<form action="https://yourworkspace.hxgconnect.com/api/capture/leads" method="post">
  <input type="hidden" name="api_key" value="hxgk_…">
  <input type="hidden" name="redirect" value="https://yoursite.com/thank-you">
  <input name="name" required>
  <input name="phone" required>
  <input name="email" type="email">
  <textarea name="message"></textarea>
  <input name="website" style="display:none" tabindex="-1" autocomplete="off"> <!-- spam trap: leave empty -->
  <button>Send</button>
</form>

From JavaScript, POST JSON to the same URL with the header x-api-key. This endpoint takes the exact field names name, phone, email, message, budget, property_type, location, project, source, utm_* and page_url, answers 201 {"ok":true}, and allows 60 leads a minute per key.

Google Forms

  1. Open the form, press the three dots, choose Apps Script.
  2. Replace the contents with the script below and paste your Google Forms address into the first line.
  3. In Apps Script open Triggers > Add trigger: function onFormSubmit, event source From form, event type On form submit. Approve the permission prompt.
const HXG_URL = 'PASTE YOUR GOOGLE FORMS ADDRESS HERE';

function onFormSubmit(e) {
  const fields = {};
  e.response.getItemResponses().forEach(function (r) {
    fields[r.getItem().getTitle()] = String(r.getResponse());
  });
  const email = e.response.getRespondentEmail();
  if (email) fields.email = email;
  UrlFetchApp.fetch(HXG_URL, {
    method: 'post', contentType: 'application/json', muteHttpExceptions: true,
    payload: JSON.stringify({ form_name: FormApp.getActiveForm().getTitle(), fields: fields })
  });
}

Question titles become the field names, so a question called "Mobile number" is read as the mobile.

  2. Optional: set a secret on the webhook and save the same value in Typeform webhook secret in HXG Connect.

Use Typeform's Phone number and Email question types so those answers are recognised whatever the question says. Hidden fields such as utm_source are kept.

IndiaMART

IndiaMART pushes each enquiry, buy-lead and call the moment it happens.

  1. Sign in at seller.indiamart.com and open Lead Manager.
  2. Three-dots menu > Push API (under Import/Export Leads).
  3. CRM: Other. Platform name: HXG Connect. Webhook URL: your IndiaMART address.
  4. Confirm the OTP sent to your primary mobile, then use IndiaMART's test button.

The buyer's name, mobile, email, company, city, product and message come through, with the enquiry type (direct enquiry, buy lead, phone call, catalogue view, WhatsApp). Retries are matched on IndiaMART's UNIQUE_QUERY_ID. IndiaMART switches Push API off if a CRM refuses leads for 48 hours, so this address always answers 200.

JustDial set up by their team

JustDial configures the push on their side. On the connector screen choose JustDial and press Email account manager: it opens a ready-written request with your address. Ask them for a test lead when it's done.

The address accepts JustDial's GET or POST delivery and answers RECEIVED.

Sulekha set up by their team

Same route as JustDial: send your Sulekha address to your account manager and ask for a test lead.

Property portals

99acres, MagicBricks, Housing.com, NoBroker, Square Yards, CommonFloor, PropTiger and Makaan have their own integration in HXG Connect: Settings > Integrations > Property portals. Two routes:

  • Forward the portal's lead emails to your private HXG Connect address. Works with every portal, and with TradeIndia and others that only email leads.
  • Direct push. 99acres and MagicBricks set this up through your account manager; the screen writes that email for you.

Facebook and Instagram lead ads

Built in: Settings > Integrations > Facebook and Instagram lead ads. Enter your Page ID, a long-lived Page token with leads_retrieval, and your Meta app secret; then add the webhook URL and verify token the screen shows to your Meta app and subscribe to leadgen.

Google Ads lead forms

Built in: Settings > Integrations > Google Ads lead forms. Paste the webhook URL and key into the lead form asset in Google Ads and press Send test data.

LinkedIn, TikTok and others

Platforms that only release leads to approved apps connect through an automation tool. In Zapier, Make or Pabbly, use the platform's own "new lead" trigger and send the lead to HXG Connect as described below.

Zapier

  1. Add the action Webhooks by Zapier > POST.
  2. URL = your Zapier address. Payload type json.
  3. Under Data add name, phone, email, message and map them from the trigger. Test the step: "Lead added" means it worked, and a 422 tells you what's missing.

Make

  1. Add HTTP > Make a request.
  2. URL = your Make address, method POST, body type Raw, content type JSON.
  3. Request content: {"name":"…","phone":"…","email":"…","message":"…"} mapped from earlier modules.

Pabbly Connect

  1. Add the action API (Pabbly) > Execute custom request.
  2. Method POST, URL = your Pabbly address, payload type JSON.
  3. Add parameters name, phone, email, message.

n8n

  1. Add an HTTP Request node: method POST, URL = your n8n address.
  2. Send body as JSON with name, phone, email, message.

Your own system

Use the Any other platform address. POST one lead per request. Add ?source= to label where the leads come from, and send your own reference so retries are safe:

POST /api/webhooks/in/custom/YOUR-KEY?source=broker_app
Content-Type: application/json
Idempotency-Key: enquiry-48213

{
  "name": "Asha Verma",
  "phone": "+919820012345",
  "email": "asha@example.com",
  "city": "Pune",
  "budget": "85L",
  "project": "Sunrise Heights",
  "message": "Wants a site visit on Saturday",
  "utm_source": "broker_app"
}

Systems that can only call a URL can use GET with the same names as query parameters.

Code samples

PHP

$ch = curl_init('https://yourworkspace.hxgconnect.com/api/webhooks/in/custom/YOUR-KEY');
curl_setopt_array($ch, [
  CURLOPT_POST => true, CURLOPT_RETURNTRANSFER => true, CURLOPT_TIMEOUT => 10,
  CURLOPT_HTTPHEADER => ['Content-Type: application/json'],
  CURLOPT_POSTFIELDS => json_encode(['name' => $name, 'phone' => $phone, 'email' => $email, 'message' => $message]),
]);
$reply = json_decode(curl_exec($ch), true);
$ok = curl_getinfo($ch, CURLINFO_RESPONSE_CODE) === 200 && $reply['status'] === 'success';

const res = await fetch('https://yourworkspace.hxgconnect.com/api/webhooks/in/custom/YOUR-KEY', {

For platform teams

If you run a lead platform and want to offer "Send to HXG Connect" to your customers, this is all you need to build:

  1. A URL field in your customer's settings where they paste their HXG Connect address. Ask them to use the Any other platform address with ?source=yourname; tell us and we'll add a named address for your platform so the lead source and setup steps carry your name.
  2. POST each lead as JSON the moment it's created, with at least a name and a mobile number. Use the field names in the table if you can; your existing names will very likely be read as they are.
  3. Send a stable reference per lead (lead_id in the body or an Idempotency-Key header).
  4. Treat 200 as delivered. On a timeout or 5xx, retry with the same reference. On 422, don't retry: show your customer the message.
  5. A test button that sends a sample lead. Your customer sees it arrive in HXG Connect's delivery log within seconds.

No approval, app listing or OAuth is involved. If your platform can only deliver by email, your customers can forward those emails instead: see Property portals.
